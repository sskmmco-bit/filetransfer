# Plan — Performance: config tier (Postgres tuning + Gunicorn + nginx static)

**Status:** completed

## Summary

Highest-impact, lowest-risk performance work for the single 4 GB / 2 vCPU Debian
host. No schema or app-logic changes — only deployment config:

1. **Tune PostgreSQL** off its tiny stock defaults via a conf.d drop-in.
2. **Gunicorn** — add `--preload` (copy-on-write shared memory → less RAM) and
   worker recycling (`--max-requests` + jitter) to bound any leak (e.g. Pillow).
3. **nginx** — serve `/static/` directly with long cache headers + gzip (offload
   static off the Python tier), and fix the stale `deploy/nginx.host.conf` that
   still references the retired Docker-compose nginx on :8080.

## Files affected

- `deploy/postgresql.tuning.conf` — **created**: drop-in with the 4 GB/2 vCPU
  values below. Installer copies it into the cluster's `conf.d/`.
- `deploy/install_no_docker.sh` — **changed**: (a) new step copies the tuning
  drop-in into `/etc/postgresql/*/main/conf.d/` and restarts `postgresql`;
  (b) Gunicorn `ExecStart` gains `--preload --max-requests 1000
  --max-requests-jitter 200`; (c) nginx server block gains a `/static/` location
  (`alias $APP/staticfiles/;` + `expires 1y; add_header Cache-Control "public,
  immutable";`) and `gzip on;` for text types.
- `deploy/wsl_test_install.sh` — **changed**: mirror the Gunicorn + nginx changes
  (skip PG tuning on the throwaway WSL box, or apply a smaller drop-in).
- `deploy/update_no_docker.sh` — **changed**: re-apply the Gunicorn unit + nginx
  config (and PG drop-in) idempotently on update.
- `deploy/nginx.host.conf` — **changed**: rewrite to the no-Docker reality
  (proxy to `127.0.0.1:8000`, `/static/` alias, `/mmftp-files/` → MinIO); drop the
  `:8080`/`docker compose up -d web worker beat` references.
- `deploy/INSTALL_NO_DOCKER.md` — **changed**: document the PG tuning step, the new
  Gunicorn flags, and the nginx `/static/` + gzip block.

### Recommended postgresql.tuning.conf (4 GB / 2 vCPU, SSD)
```
shared_buffers = 512MB
effective_cache_size = 2GB
work_mem = 16MB
maintenance_work_mem = 256MB
max_connections = 50
random_page_cost = 1.1
effective_io_concurrency = 200
checkpoint_completion_target = 0.9
wal_compression = on
```
(`synchronous_commit` left at `on` — file-metadata durability > marginal write gain.)

## Database changes

None. PostgreSQL **server** configuration only — no schema, models, or migrations.

## Effect on the current system

- **Runtime:** faster queries (bigger buffers/cache hints), lower Gunicorn RAM via
  `--preload`, static assets served by nginx instead of Python, smaller responses
  via gzip. No behavior change.
- **Memory:** `shared_buffers=512MB` chosen conservatively so Postgres + 3 Gunicorn
  workers + MinIO coexist on 4 GB without swap.
- **Services to restart/reload:** `postgresql` (restart — `shared_buffers` needs
  it), `mmftp-web` (restart — new ExecStart), `nginx` (reload). Job timers
  unaffected.
- **Config/secrets:** none.
- **Rollback:** delete the conf.d drop-in + restart Postgres; revert the unit/nginx
  files. No data risk.
- **Compatibility:** `/static/` alias requires `collectstatic` to have populated
  `$APP/staticfiles/` (already part of install). `max_connections=50` is well above
  the app's ceiling (workers×threads ≈ 9 + job runs).
