# Change log — Performance: config tier (Postgres + Gunicorn + nginx)

**Plan:** `plans/20260625_160511_perf-config-tier.md`
**Date:** 2026-06-25

## What was changed

Deployment-config-only performance work for the 4 GB / 2 vCPU host. No schema/app
logic.

- `deploy/postgresql.tuning.conf` — **created**: 4 GB/2 vCPU drop-in
  (`shared_buffers=512MB`, `effective_cache_size=2GB`, `work_mem=16MB`,
  `maintenance_work_mem=256MB`, `max_connections=50`, `random_page_cost=1.1`,
  `effective_io_concurrency=200`, `checkpoint_completion_target=0.9`,
  `wal_compression=on`; `synchronous_commit` left on).
- `deploy/install_no_docker.sh` — **changed**: new STEP 1b copies the tuning
  drop-in to `/etc/postgresql/*/main/conf.d/10-mmftp-tuning.conf` and restarts
  postgresql; Gunicorn `ExecStart` gained `--preload --max-requests 1000
  --max-requests-jitter 200`; nginx server block gained `gzip on`, a `/static/`
  location (`alias $APP/staticfiles/` + 1y immutable cache) — substituted via
  `sed APP_PATH`.
- `deploy/wsl_test_install.sh` — **changed**: mirrored the Gunicorn flags + nginx
  `/static/` + gzip (no PG tuning on the throwaway box).
- `deploy/update_no_docker.sh` — **changed**: new "4b" block re-writes the
  `mmftp-web` unit (so `--preload` reaches existing installs), rewrites the nginx
  config (static/gzip), and re-applies the PG tuning drop-in on every update.
- `deploy/nginx.host.conf` — **rewritten**: dropped the stale Docker-compose
  references (`:8080`, `docker compose up -d web worker beat`); now reflects the
  no-Docker reality (proxy → `127.0.0.1:8000`, `/static/` alias, `/mmftp-files/` →
  MinIO, gzip), with a matching HTTPS block.
- `deploy/INSTALL_NO_DOCKER.md` — **changed**: timer/service references updated
  (see thumbnails change log; same edit pass).
